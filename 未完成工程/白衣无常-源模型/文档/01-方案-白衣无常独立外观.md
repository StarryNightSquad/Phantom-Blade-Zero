### 5.6 usmap 从哪来（20:45 查证，回答用户提问）

- **【UE4SS 官方 docs《Dumpers】**：`.usmap` Dumper 为 **unversioned properties** 生成映射，
  默认 `Ctrl + Numpad 6` / `DumpUSMAP()`，源自 OutTheShade 的 UnrealMappingsDumper；
  `.jmap` 另含完整反射数据，jmap CLI 可转 `.usmap`。
- **【社区资料】**：UE5 cooked 资产把属性名剥离、按索引序列化，没有匹配 usmap 时
  FModel/CUE4Parse/retoc 读类属性只能看到 blob；**但模型、贴图等表层资产仍可浏览导出**
  （The Forever Winter wiki / PAYDAY3 modding docs）。`AssetRegistry.bin` 只是资产目录，
  与 usmap 不是一回事。
- **结论**：usmap 的数据源是**运行时引擎反射系统**（编译进 exe/dll 的 C++ 类型 + 蓝图类型），
  **不在资产文件里 → 不能从本地 pak/uasset「提取」**。两条获取路径：
  ① 下载社区现成；② UE4SS / Dumper-7 启动一次游戏 dump。
- **本机实测**：PBZ 已有 `platform/steam/ue4ss/ProjectPBZ-5.7.4-301524+42ecbfa37f78-1ceefac8.usmap`
  （4,778,099 B，magic `0x30C4` + version `4`，UE4SS 生成）→ **主线不缺**。
  明末：全目录、所有下载 zip、PBZ 侧均**未找到** `*.usmap`；没有 UE4SS
  （只有游戏自带 `xinput1_3.dll` 107,368 B，两处）；manifest 里的 `Project_Plague/AssetRegistry.bin`
  不是 usmap。
- **现成来源**：AyakaMods「Wuchang Unreal Mappings .usmap for FModel 1.7」419.9 KB，
  UE 5.1.1，AES key 与《技术说明》一致，2026-01-23，**需登录/注册才能下载**；
  LoversLab 2025-07-24 有人附 `Mappings.zip` 413.04 kB（同样需登录）。
- **对本项目**：明末 usmap 只在增强线（从 `cloth01` 取原始发簪/头发、读材质属性或 DataTable）
  才可能需要；主线与已做的 locres 反查都不依赖它。
- **【23:05 结果】已自行生成并验证**：`github_wip/usmap/Project_Plague-UE5.1.1.usmap`
  （1.36 MB，magic `0x30C4` / **version 0**），CUE4Parse `USMAP_LOAD_OK`，
  含 `SpringStiffness` / `SpringDamping` / `TrailBone`；UE4SS 已完整卸载。详见 §7。

### 5.7 「分部分 / 分层」结构实证与偶发部件消失（21:58，用户第 17 条）

**用户实测**：作者移植的海寇套偶发「左胸布条消失 → 躯干部分裸露」，触发条件不明；
加上此前的面部 / 马尾偶发，用户判断作者是**分部分或分层制作**，导致偶发某个部件意外消失。

**【实测 · 资产清单】作者的「层」不是多个网格，而是单网格的多个材质槽（section）**
`Corsair_3304` 包（155 资产）只有 2 个主体网格 `SK_CorsairBody` / `SK_CorsairHead`
（另有 `SK_WuchangEyeShadow`），但配了：
- `PBZFourOutfits/MaterialInstances/` **16 个 `MI_FO_<hash>.uasset`**
- `PBZFourOutfits/Parents/` 三个母材质 `M_Four_masked` / `M_Four_opaque` / `M_Four_hair`
- `PBZFourOutfits/Defaults/` 的 `T_Opacity` / `T_Mask` / `T_White` / `T_FlatNormal`
- `PBZFourOutfits/TexturesVT/` **88 张** `T_FO_<hash>_{C,ARM,N}`（每个 hash 一套贴图）

→ 一个 body 网格按约 16 个 section 分层，每层一个 MI + 一套贴图。「左胸布条」是其中
一个 section 而非独立物体；它消失 = 该 section 不渲染，露出同一网格更里层的躯干 ——
**正好解释「躯干部分裸露」**。

**【实测 · 明末原版】原版本来就是按部位分件 + alpha 抠形**
`cloth01` 网格 `KouZhi_Jacket / Hands / Pants / Hat`；材质按部位命名 `Met/shangyi`（上衣）、
`shangyi_3`、`lingjian`（领肩）、`pifeng`（披风）、`hubi`（护臂）、`shoutao`（手套）、
`tui`（腿）、`fazhan`（发簪）、`yumao`（羽毛）…；贴图 `wuchang_low_<部位>_{Albedo,Normal,Reflection}`，
并有 **`Tex/T_KouZhi_Mask.uasset`** 遮罩贴图。→ 用户的分层判断成立，移植后保留为 section 分层。

**【实测 · 运行时层】多个 GameFeature 组件在管部件显隐 / 切换**
`BPC_CollectionHeadCloth`、`BPC_WardrobeHeadHandoff`、`BPC_MingMoHairResidency`
（均在 `ProjectPBZ/Plugins/GameFeatures/*/Content/`），另有 `PP_CorsairBodyExecution` 物理资产。
它们具备「动态改某一层显示状态」的机制条件。

**【推断，依据如上，不是结论】**：三类偶发消失（面部 / 马尾 / 左胸布条）＋资产 hash 完全不变
→ 同一根因类别：**运行时组件切换的状态竞态**，不是资产缺失。最可能的机制是某个
`M_Four_masked` section 的 Opacity Mask 参数或贴图在切换中没生效，导致整片布条全透明。
**触发条件静态资产里看不出来**，需要运行时日志或更多实测。

**【对我们 mod 的影响 · 可操作】**
