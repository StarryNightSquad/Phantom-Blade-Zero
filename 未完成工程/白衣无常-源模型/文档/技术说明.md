## 一、一条铁律：从头做，不在旧文件上打补丁

前一阶段的问题全部来自「反复修」：

- 每轮脚本在上一版 FBX 上再处理一次，`use_mesh_modifiers=True` 会把骨架变形烘进顶点，**每过一轮就叠加一次**；
- `join()` 会把新对象的材质槽重映射到旧槽位，槽名错乱后只能靠猜；
- 修一个问题引入两个新问题，最后没人知道哪一版是对的。

因此本次**全部从明末原厂 glb 重新读取**，旧 FBX 一个都没用。管线写成一次性脚本（`scripts/build.py`），任何调整都重新跑一遍全流程，不做增量修改。

### 明末的服装是「各部位自带身体段」，不是「裸体套衣服」

这一点必须先搞清楚，否则会误判某些装饰该不该存在。

**实测各部位的皮肤（`MI_Body`）覆盖高度：**

| 部件 | 皮肤 z 范围 | 面数 | 覆盖 |
|---|---|---|---|
| `WUCH_BWC_Jacket` | 1.120 ~ 1.516 | 3,254 | 仅躯干 |
| `WUCH_BWC_Hands` | 0.856 ~ 1.199 | 4,100 | 手臂 |
| `WUCH_NvJuan_Hands` | 0.856 ~ 1.198 | 33,072 | 手臂（同范围，可互换） |
| `WuCh_BLYR_Pants` | **0.015 ~ 1.142** | 8,752 | **脚底到腰，含下体** |

**结论**：每个部位都是一段**完整的身体 + 对应的衣服**，在拼接处（约 1.12~1.14）互相重叠遮挡。
并不存在一个「所有套装共用的裸体底模」——

- 下装自带整条腿（含阴部），所以换了鞋子就换了整段下半身；
- 手自带手臂皮肤，所以换手就换整条手臂；
- 上装自带躯干皮肤。

所谓「默认裸体」只是**某个部位没有对应套装时的兜底**，不是公共底模。

**实践含义**：混搭不同套装的不同部位是**合法**的（这正是游戏的模块化设计），
只要注意：
1. 三个部位的皮肤贴图是同一张 `T_Body_D`，拼接处不会色差；
2. 拼接处会重叠，靠衣服遮盖，不做缝合。

## 三、管线原理：为什么顶点位置完全不动

### 走过的弯路

最初采用标准重定向公式：

```
v' = Σ wᵢ · (BindPose_PBZ(骨ᵢ) · Scale100 · BindPose_明末(骨ᵢ)⁻¹) · v
```

理论上这是正确的「把明末 rest 姿势搬到 PBZ rest 姿势」的做法。**实测结果：三套模型的躯干扭曲、脚掌向下折 90°、小腿变细。**

原因：这个公式在数学上做的是**逐骨刚性变换**。只有当两套骨架的 rest 姿势**朝向一致**时，形状才保持。而：

- 明末是**平脚**站姿；
- PBZ 是**绷脚/高跟**姿势；
- 两套骨架的骨骼 roll（局部坐标轴朝向）大量不同。

于是每个顶点被它所属骨骼「拧」了一下，几十根骨叠起来就是整体扭曲。脚部差异最大，所以脚直接折断。

### 最终方案：刚性对齐（`mode: "rigid"`）

```
v' = v × 100        // 只做米 → 厘米的单位换算，完全不改变形状
权重按骨名映射到 PBZ 骨骼
```

- **形状 100% 保持**，绝对不会扭曲；
- 代价：网格与 PBZ 骨骼的 bind 位置有少量偏差（因为两套骨架身高比例略有不同），这个偏差交给封包侧的 retarget / 绑定修正。

这是本次最重要的决定：**优先保证模型外观正确**，绑定精度的残余问题明确交接，而不是用一种"看起来更严格但会毁掉形状"的方法。

## 四、踩过的坑（按严重程度）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 躯干扭曲、脚掌折 90°、小腿变细 | 逐骨 bind 变换遇上两套不同的 rest 姿势 | 改刚性对齐（见上） |
| 2 | 布料被拖到脚底 −103 cm | 用「距离最近的核心骨」判断肢体归属，把 `Xiuzi_1~7`（从腰垂到小腿的飘带骨链）判成了脚 | 改为**沿父链定肢体、再按位置定段**；且只有真正贴着骨段的骨才细化到 twist |
| 3 | 顶点被旋转到奇怪位置 | 目标骨和参考骨不配套（目标用 twist 骨、参考还停在上一个关节） | 目标骨与参考骨必须来自同一段 |
| 4 | 身体比头大 100 倍 | 明末 glb 是**米**、PBZ 骨架是**厘米**、作者的头 glb 也是**米** | 头单独 ×100，身体走 rigid 的 ×100 |
| 5 | 女眷手出现飞点 | 明末部分手有第 4 节指骨，PBZ 只有 3 节 | `Finger4` 并入 `_03`；手腕/脚踝的辅助骨（`SWrist`、`Weapon_Hand`、`SFoot`）刚性跟手/脚，不塞进上一段 |
| 6 | 包围盒被撑到 −110 cm | 个别顶点权重 100% 挂在 `Root` 上（垃圾顶点），只有 4 个 | 剔除人体范围外（z < −20 或 > 250 cm）的孤立顶点 |
| 7 | 7 个 UV 层全是空的 | `probe_uv` 读到空层 | 主 UV 是第一层 `UVMap` |
| 8 | 渲染白屏 | 相机距离远超默认 `clip_end=100`（厘米场景） | `clip_end = 100000` |

## 五、纸钱：原设计就是圆的，不需要改

**结论：这一节最终什么都没做。** 记录过程是为了避免以后再绕同样的弯路。

### 曾经误判的三次

**误判一：把「方块」当成错误设计。**

用纯色（分色）渲染检查模型时，裙面上那些片看起来是方块。于是判断"原设计是方块，需要改成铜钱形"。
实际原因：**分色渲染不显示贴图 alpha**。原模型的片是靠贴图 alpha 抠形的，纯色下只能看到几何轮廓（矩形）。

**误判二：去腰带贴图上找铜钱。**

白衣无常的**腰带**（`M_HWC_YaoDai01`）背面确实垂着 **7 枚铜钱几何**（每枚 20 面 20 顶点），贴图 `T_Highres_BWC_YD_D` 顶部也有铜钱图案。
但那是**后腰的独立装饰**，与裙上的纸钱无关。误把两者混为一谈后，一度把铜钱几何复制到裙前、还放大 2.5 倍。

**误判三：自己造 alpha 和几何。**

先后尝试过：裁腰带铜钱 + 自动搜索圆心半径生成圆形 alpha、生成 20 段圆环真几何、UV 重映射到铜钱图案……全是多余的。

### 正确的事实

`T_Highres_BWC_QZ_D` 的 **alpha 通道左侧有一列「圆形带方孔」的镂空图案**（5 枚圆钱 + 3 个椭圆），这就是原版的白色纸钱。

裙上那些片的 UV 本来就指向那里，**只要材质按原设计配 alpha（Masked），渲染出来就是标准纸钱**。

按原贴图 + alpha 渲染的实拍见：`views/orig_zhijian.png`


### 渲染必须用 REPEAT，不能用 CLIP（重要）

**现象**：女眷手腕的红装饰只有右臂有，左臂完全没有。几何数据是 2346 : 2346 完全对称，法线也对称。

**根因**：左右两侧 UV 不对称 ——

```
左臂 UV u[0.5923, 0.7266]   ← 在 0~1 内
右臂 UV u[0.6479, 1.7266]   ← 溢出到 1.73
```

原模型允许 UV 超出 0~1，靠贴图的 **REPEAT（平铺）** 回绕。而我渲染时把寻址模式设成了 **CLIP**（超出即透明），于是右臂整段被裁成透明、直接消失。

**结论**：渲染任何明末资产，贴图寻址必须是 **REPEAT**。用 CLIP 会让所有 UV 溢出的部件凭空消失，看起来像"模型缺失"。

> 这个坑同样会让人误判「某个部件没做出来」—— 实际上它可能只是被 CLIP 裁掉了。

### 交接要求

裙材质 `M_HWC_Qunzi` 必须配成 **Masked**，Base Color 与 Opacity Mask 都用 `T_Highres_BWC_QZ_D.png`（Opacity 取其 Alpha 通道），Two Sided 开启。

> 同样的坑在其它套装上也存在：**检查任何「片状/镂空」部件前，必须先用贴图 + alpha 渲染一次**，
> 不要用纯色渲染下结论。纯色渲染会把所有 alpha 抠形的东西显示成矩形。

- 胸口的骷髅与肋骨是原设计，**保留**。

### 婉若游龙的裙

「左长右裸」是**本体上装自带的设计**（画面右侧/角色左侧垂到脚踝，另一侧开叉到大腿），不需要裁剪。
曾经因为它看起来「两侧都有」而怀疑资源找错 —— 实际是逐骨变换造成的扭曲假象，改用刚性对齐后自然恢复正常。

## 七、已知限制 / 留给接手方

> **交付的只有「模型 + 材质槽名」。** 下面三类问题必须接手方处理，否则进游戏会出错。
> **不要假设「拿到 FBX 就能直接用」。**

### 7.1 模型层面（材质配得再对也救不回来）

#### （1）骨骼 bind 有偏差 —— 最大风险

顶点只做了 ×100 单位换算，**没有做逐骨 bind 变换**（原因见第三节）。后果：

- 静止 / 待机动作：形状正确
- **播放动画：网格与 PBZ 骨骼的 bind 位置对不齐，可能出现局部穿插、错位、拉扯**

这是设计时就明确交接的问题。处理方式：UE 里用 IK Retargeter 转一道，或手动修 bind pose。

#### （2）布料模拟完全缺失

glb / FBX **不携带任何物理数据**。以下部位进游戏后是**硬的**，不会飘：

| 部位 | 应有物理 | 现状 |
|---|---|---|
| 裙摆（三套都有） | Cloth | **无** |
| 纸钱片（白衣无常，裙前那一串） | Cloth | **无** |
| 腰侧长布条（`M_HWC_shoubi` 的下垂部分） | Cloth | **无** |
| 肩部羽簇（流云织羽 `yumao`） | Cloth | **无** |
| 流苏 / 飘带 | Cloth | **无** |

**需要在 UE 里为这些网格单独建 Cloth Asset、刷布料权重、配碰撞体。** 这部分工作量为零，完全没做。

#### （3）拼接处是重叠，不是缝合

上装（躯干 1.12~1.52）/ 手（手臂 0.86~1.20）/ 下装（腿 0.015~1.14）在 **1.12~1.14** 处几何重叠，靠衣服遮盖。
常规姿势看不出，**大幅度动作可能露出接缝**。

### 7.2 材质层面（必须逐项配，漏一项就错）

| 项 | 要求 | 不配的后果 |
|---|---|---|
| 皮肤 | 三套统一 `Wuchang_Base/Tex/BODY/T_Body_D` | 肤色发灰、拼接处色差 |
| 纸钱 | `M_HWC_Qunzi` 配 **Masked** + `T_Highres_BWC_QZ_D` 的 Alpha 通道 | 显示成方块 |
| 护臂 / 腰带 / 胸骨 | 用原父材质 `M_B_CharacterMask_SP` + `T_HWC_Mask` | 纽扣金属感、布料哑光全错 |
| 指甲 | `cloth01/Tex/Nails_BaseColor`（粉红色） | 显示纯白 |
| 双面 | 纸钱、镂空花边开 Two Sided | 背面透明 |
| alpha 阈值 | Masked 的 threshold **不要高于 0.2** | 镂空被放大，露出内层皮肤形成色块 |

完整映射表见「二·补二」。

### 7.3 验证状态（重要）

**所有结论都只在 Blender 里做过渲染验证，没有一次进游戏实测。**

- 材质映射：靠读 uasset 引用 + 渲染比对确认
- 骨骼 / 权重：靠数据统计确认（1134 骨全匹配、每顶点 ≤4 骨且归一化）
- **但动画表现、布料效果、游戏内实际观感 —— 全部未验证**

**建议**：先封**流云织羽**（部件最少：上装 + 下装 + 手 + 头）进游戏跑一遍，确认 bind 没问题，再批量处理另外两套。

### 7.4 其它

- **鞋底高度**：白衣无常的细带高跟未做抬高（按需求交由封包侧决定）
- **婉若游龙的色块**：原始材质用 `T_WuCh_LTZ_FG1/FG2/FG4_MASK` 做多层混合，简化渲染只接单层 base color，所以截图里身体会有轻微深浅分块。**模型本身没问题**，UE 里按原材质搭就正常。
